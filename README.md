# 🏋️‍♂️ monolith-bodybuilder

> "If your computer can't handle the weight, get out of the cloud."

`monolith-bodybuilder` is a brutalist, hyper-heavy backend framework designed for developer-bodybuilders who refuse modern, flimsy trends like microservices, Docker containers, or separate files. 

Inspired by the ultimate alpha physique—naked to the core, standing unbothered in a backyard, wearing nothing but a wide-open hoodie—this framework runs **bare-metal, completely exposed, and takes up 100% of your machine's soul.**

## 💪 Philosophy

1. **One Body, One File:** Splitting code into multiple folders is a sign of structural weakness. Database models, routing, business logic, HTML templates, and state management must live in a single, unreadable `server.py`.
2. **RAM Domination:** If an application isn't chugging 100% of your memory upon startup, it's not trying hard enough. We deliberately flex your CPU on initialization.
3. **No Safety Nets:** We do not run inside containers. Containers are clothes, and this framework runs entirely naked ("Bare-Metal") directly on your host machine.

---

## 🚀 Installation & Usage

Since this framework is too heavy for package managers like `pip`, you don't install it. You simply clone the file and let your hardware pray.

```bash
python server.py
```

---

## 🛠️ API Endpoints & Features

Every endpoint is designed to assert dominance over the client:

* `GET /` — Returns a raw brute-force HTML greeting.
* `POST /lift` — Simulates adding weight to the database. If you lift too much, it triggers an intentional memory pump.
* `GET /flex` — Displays current machine statistics while mocking your puny RAM capacity.
* `GET /admin` — Protected by a pure physical authentication wall (no JWTs allowed).
